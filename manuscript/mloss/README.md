# fastEmbedR JMLR-MLOSS manuscript

This directory contains the four-page JMLR-MLOSS description and a separate
supplementary document.

## Files

- `fastEmbedR_MLOSS.tex`: four-page software description, followed by real
  benchmark figures and references.
- `fastEmbedR_MLOSS_supplement.tex`: implementation, API, validation,
  landmarking, data, and reproducibility details.
- `deliverables/`: submission-ready manuscript and supplement files, rendered
  HTML and PDF vignettes, and the generated package reference manual.
- `fastEmbedR_MLOSS.bib`: shared bibliography.
- `jmlr2e.sty`: unmodified official JMLR style file from commit
  `f413f638b407af76074813f8f88a82a7a5a81e9d` of
  <https://github.com/JmlrOrg/jmlr-style-file>.
- `figures/`: archived MNIST70k benchmark outputs generated by the package
  benchmark script. No synthetic architecture illustration is included.
- `generated/python_non_kodama_runs.csv`: seed-level Python rows with explicit
  `timing_scope` and `runtime_measure` fields.
- `generated/python_summary_median.csv`: three-seed Python summaries with
  R-mediated total-call time, direct-Python fit time, and direct subprocess
  wall time in separate columns.
- `generated/runtime_tsne_all_methods.csv` and
  `generated/runtime_umap_all_methods.csv`: exact plotted rows. A direct-Python
  value is never stored in the R-mediated total-call column.

Python timing uses three distinct fields:
`r_mediated_total_call_sec` includes the R/Python boundary, conversion,
transfer, fitting, and return conversion; `direct_python_fit_sec` records only
the Python model call; and `direct_python_process_total_sec` records direct
subprocess startup, input loading, fitting, and output writing.

## Build

Run from this directory:

```bash
latexmk -pdf -interaction=nonstopmode -halt-on-error fastEmbedR_MLOSS.tex
latexmk -pdf -interaction=nonstopmode -halt-on-error fastEmbedR_MLOSS_supplement.tex
```

The files compile with `pdflatex` through `latexmk`, as required by the JMLR
author guide. Hyperlinks use `hidelinks`; page geometry and `jmlr2e.sty` are
not modified.
